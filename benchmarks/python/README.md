# Public Black benchmark preparation

`black.json` pins the public Black commit, upstream MIT license, the exact
parser-invalid test-file deletion list, prepared Git identities and the
digests of the frozen benchmark inputs. `LICENSE.black` preserves Black's
license. The anchors include verbatim decorator and call-expression excerpts
from Black under its MIT license, including multi-line expressions, comments
and string literals. No complete source files or encoded source payloads are
included.

The oracle and anchors retain the independently frozen facts and labels from
the accepted Python benchmark. They have not been relabelled against new
extractor output. The existing scorer checks complete selected bodies,
unsupported sites, forbidden edges and unchanged acceptance thresholds.
`black-query.json` retains the frozen native input paths, source hashes and
package profile; preparation reconstructs its source payload from the public
checkout. The anchors cover Python modules and selected declarations, as
required by the existing benchmark bridge.

## Closed operator preparation

`black-operator.json` pins the public CPython 3.14.7 archive, mypy 2.3.1 Git
commit and five dependency wheels for macOS arm64. Download the archive and
wheels from its recorded URLs into local input directories. Check out the
declared mypy commit with origin `https://github.com/python/mypy.git`.
Install the Ruby dependencies used by the helpers:

```sh
gem install tty-option:0.3.0 tty-prompt:0.23.1 tty-command:0.10.1 rubyzip:3.7.0
```

Select the host's actual dyld cache family explicitly, then run:

```sh
bin/prepare-black-operator --archive /local/cpython.tar.gz --compiler /local/mypy --wheels /local/wheels --cache-directory /System/Volumes/Preboot/Cryptexes/OS/System/Library/dyld --cache-prefix dyld_shared_cache_arm64e --out /local/new-operator
```

The command checks every archive digest and the clean public compiler commit
before copying. The closed runtime contains the pinned archive's interpreter
and stdlib, with generated bytecode caches and site packages excluded. Local
installation caches and relocated build configuration are not inputs. Only
committed mypy/mypyc blobs enter the compiler root; dependencies are extracted
directly from their verified wheels. No install scripts, application modules
or compiler queries execute during preparation.

Invalid archive paths, links and oversized copied files are refused, and
prepared file writes cannot overwrite existing files. TAR names use the
format's NUL terminator before logical-path validation. The prepared runtime
retains its Python license; mypy's license
is copied beside the compiler, and wheel notices remain with their packages.

The helper hashes the entire selected cache family and the four standard
macOS sandbox/inspection tools named in `black-operator.json`. These are
observed content pins, not execution witnesses. The guarded extractor must
still verify the selected interpreter, loaded images, read scope and unchanged
inputs during actual extraction.

The new output directory stays outside Git and contains `runtime/`,
`compiler/`, `native-config.json`, `LICENSE.mypy` and `result.json`. The receipt
records public input pins, path-independent input-inventory digests and the
generated config digest. It does not grant semantic acceptance. Preparation
has no network operations; downloads happen explicitly before it runs.

## Source preparation and benchmark

Prepare a clean checkout at `original_commit`, then use the prepared operator's
CPython 3.14.7 interpreter from Stele:

```sh
bin/prepare-black --repo /local/black --python /local/new-operator/runtime/bin/python3.14 --out /local/new-black-inputs
```

The checkout's origin must be `https://github.com/psf/black.git`. The command
requires a new output directory outside Git. It checks the owned parser's
digest and runs `ast.parse(..., type_comments=True)`, then compile and scope
checks on every tracked `.py` and `.pyi` file. Plain `compile()` accepts the
`type_comment_syntax_error.py` fixture; the pinned parser mode rejects its
invalid type comment. Checking with plain `compile()` therefore produces a
smaller rejection set. Corpus modules are never imported or executed. The rejected
set must equal the frozen deletion list; unexpected parser failures abort.
Every kept input must pass. No removed path may overlap the anchors, labels
or native query. Preparation deletes only that frozen set, then requires the
expected prepared tree and deterministic commit. No benchmark branch or
commit is added to the caller's source repository.

The local output contains `prepared/` and `clone/` checkouts with the public
origin, `bridge.json`, reconstructed `query.json`, a parser input inventory
and `result.json`. The receipt records input/output digests and kept/removed
counts. It grants no new semantic claims. The existing `bin/python-benchmark`
independently verifies the bridge and scores the oracle; use the receipt's
digests when supplying its bridge and query options. The committed oracle
and anchor digests are in `black.json`.

Pass `/local/new-operator/native-config.json` as `--config` to
`bin/python-benchmark`, alongside the original checkout, prepared and clone
checkouts, frozen oracle/anchors and reconstructed bridge/query. Use pins from
`black.json` and the source-preparation receipt. The benchmark checks the
original tree's refusal, repeated and clone extraction, validated snapshot
equality, frozen labels and forbidden edges, and refusal after declared-input
drift. It establishes execution and semantic results separately from the two
preparation commands. Keep snapshots, logs, measurements and source payloads
outside Git.

On macOS arm64, the public-archive recipe passed the actual guarded native
benchmark against the unchanged frozen oracle. Original-source and
declared-input-drift refusals passed, and repeated and clone extractions
produced byte-identical validated snapshots. Other platforms and operator
profiles are not asserted to have passed; preparation and a logical model
alone do not establish execution results.
